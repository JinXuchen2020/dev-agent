# F15 · 多语言国际化（i18n，暂仅中文 + 英文）  [P1]

> 设计文档（features/ 设计枢纽）。本 feature 为前端跨切面改造，范围明确为 **zh-CN + en-US 两套语言**，属 🟡中风险（涉及几乎所有前端页面的文案抽取 + 全局 Provider 注入；不触后端契约，但工作量大、需统一的 key 规范）。
>
> 一句话：引入 `i18next` + `react-i18next`，在顶栏提供「中文 / English」切换，持久化到 localStorage；Antd `ConfigProvider` 与 `dayjs` 同步切换区域；v1 优先抽取所有 UI 框架级文案（导航 / 标题 / 按钮 / 表单标签 / 空态 / 错误态），领域内容（agent 描述等）后续再补。

## §1 目标
当前前端全部文案为硬编码中文（`LoginPage` / `AppLayout` 菜单 / 各页标题按钮 / 表单标签 / `ErrorState` / `message.*`）。用户要求支持多语言，第一阶段只做**中文 + 英文**。

本 feature 交付：
- 国际化基础设施：`react-i18next` 实例 + `zh-CN` / `en-US` 两套资源包。
- 语言切换器：顶栏「中文 / English」`Dropdown`/`Select`，切换即时生效；
- 偏好持久化：选中的语言写入 `localStorage`（key `app-locale`），刷新不丢，默认 `zh-CN`；
- UI 框架级文案双语化：导航菜单、页标题、主按钮、表单标签、`Empty`/`ErrorState`/`message.*` 提示；
- 与 Antd 5 区域联动：`ConfigProvider locale` 切 `zh_CN`/`en_US`，`dayjs` 切 `zh-cn`/`en`，保证日期选择器/分页等组件自带文案同步。

范围**仅前端**。后端 API 错误文案（如 discovery 的「API Key 无效或无权访问」）v1 **保持原样**，前端直接展示；后端错误文案的本地化列为后续决策（见 §6 D1）。

## §2 现状核验（已读真实代码，非臆测）
- **框架**：React 19 + Vite + TS（strict）+ Antd 5（`AppLayout.tsx` 用 `antd` 组件，`ConfigProvider` 已在 `main.tsx` 或 `App.tsx` 包裹）；无既有 i18n 库（全局 grep `i18n` / `react-i18next` 应为空）。
- **文案分布**：硬编码中文散落于
  - `AppLayout.tsx`（侧边栏 `Menu` `label`、顶栏标题）；
  - 各 `pages/*.tsx`（页标题 `Typography.Title`、按钮 `新增/保存/删除/取消`、表格列头、空态 `Empty description`）；
  - `components/CredentialForm.tsx` / `CredentialManager.tsx`（表单标签、`message.success/error` 文案）；
  - `components/ErrorState.tsx` / `useApiState`（`message.warning/error`）；
  - `LoginPage.tsx`（`Form.Item label`、按钮「登录」、错误提示）。
- **Antd 区域**：Antd 5 自带 `antd/locale/zh_CN` 与 `antd/locale/en_US`；`dayjs` 自带 `zh-cn` / `en` locale，注入即可。
- **状态管理**：现有 `zustand`（`appStore.ts`）；语言偏好可放 `localStorage` 即可，不强制进 store（避免 SSR/初始化时序问题）。

## §3 拟改接口契约 / 架构

### 3.1 依赖
- 新增 `i18next` + `react-i18next`（前端 `package.json` devDeps/dependencies）。
- 不引入后端依赖（v1 纯前端）。

### 3.2 资源包结构
```
src/locales/
  index.ts        // 初始化 i18n 实例、合并资源、导出 i18n + 类型
  zh-CN.ts        // 中文资源（默认）
  en-US.ts        // 英文资源
  config.ts       // SUPPORTED_LOCALES = ['zh-CN','en-US']、DEFAULT_LOCALE='zh-CN'、STORAGE_KEY='app-locale'
```
- 资源用**嵌套对象**按 UI 区域分命名空间，示例：
  ```ts
  // zh-CN.ts
  export const zhCN = {
    common: { save: '保存', cancel: '取消', delete: '删除', create: '新建', confirm: '确认', loading: '加载中…' },
    nav: { dashboard: '仪表盘', agents: '智能体', workflows: '工作流', conversations: '对话', knowledge: '知识库', credentials: '我的凭据', research: '调研' },
    login: { title: '登录', username: '用户名', password: '密码', submit: '登录', failed: '登录失败，请检查凭据' },
    credentials: { addModel: '添加模型凭据', apiKey: 'API Key', baseUrl: 'Base URL', modelName: '模型名称', provider: '供应商', fetchModels: '拉取模型', name: '名称', enabled: '启用' },
    errors: { generic: '出错了，请稍后重试', notFound: '页面不存在', unauthorized: '未授权，请重新登录' },
    // … 其余页面标题/按钮/空态
  };
  ```
  `en-US.ts` 同结构同 key，值为英文。
- key 命名规范：`{area}.{element}` 或 `{page}.{section}.{label}`，全小写点分隔；**禁止**在 key 里拼变量值（动态文本用 `t('key', { name })` 插值）。

### 3.3 i18n 初始化（`src/locales/index.ts`）
```ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import { zhCN } from './zh-CN';
import { enUS } from './en-US';
import { DEFAULT_LOCALE, SUPPORTED_LOCALES, STORAGE_KEY } from './config';

const stored = localStorage.getItem(STORAGE_KEY) as string | null;
const initial = stored && SUPPORTED_LOCALES.includes(stored) ? stored : DEFAULT_LOCALE;

i18n.use(initReactI18next).init({
  resources: { 'zh-CN': { translation: zhCN }, 'en-US': { translation: enUS } },
  lng: initial,
  fallbackLng: DEFAULT_LOCALE,
  interpolation: { escapeValue: false }, // React 已防 XSS
});

export { i18n, SUPPORTED_LOCALES, STORAGE_KEY };
```

### 3.4 切换器 + 全局联动
- 新增 `components/LanguageSwitcher.tsx`：
  - `Dropdown` 菜单项 `中文` / `English`，或 `Segmented`；`value = i18n.language`。
  - `onClick/onChange`：`i18n.changeLanguage(lang)` + `localStorage.setItem(STORAGE_KEY, lang)` + 调用一个 `applyAntdLocale(lang)` 回调（见下）。
- `App.tsx`（或 `AppLayout` 顶层）：
  ```tsx
  const [antdLocale, setAntdLocale] = useState<AntdLocale>(i18n.language === 'en-US' ? enUS : zhCN);
  const [dayjsLocale, setDayjsLocale] = useState<string>(i18n.language === 'en-US' ? 'en' : 'zh-cn');
  useEffect(() => {
    const h = (lng: string) => {
      setAntdLocale(lng === 'en-US' ? enUS : zhCN);
      dayjs.locale(lng === 'en-US' ? 'en' : 'zh-cn');
    };
    i18n.on('languageChanged', h);
    return () => i18n.off('languageChanged', h);
  }, []);
  return <ConfigProvider locale={antdLocale}><App>{children}</App></ConfigProvider>;
  ```
  （`import zhCN from 'antd/locale/zh_CN'; import enUS from 'antd/locale/en_US'; import dayjs from 'dayjs'; import 'dayjs/locale/zh-cn'; import 'dayjs/locale/en';`）
- 把 `<LanguageSwitcher />` 放入 `AppLayout` 顶栏（右上角，用户态旁）。

### 3.5 页面 / 组件改造
- 每个需双语的组件：`import { useTranslation } from 'react-i18next'; const { t } = useTranslation();` 然后把硬编码中文替换为 `t('nav.agents')` 等。
- v1 抽取优先级（建议实现顺序）：
  1. `LanguageSwitcher` + `AppLayout` 菜单 + `LoginPage`（登录是首个可见页，优先级最高）。
  2. `common` 通用词（保存/取消/删除/确认/加载）覆盖全站按钮。
  3. 各 `pages/*` 的页标题、`Empty` description、`message.*` 调用。
  4. `CredentialForm` / `CredentialManager` / `ErrorState` / `useApiState` 文案。
- **不在 v1 范围**（标注，后续补）：agent/workflow 的**用户自定义描述文本**（属领域数据，不应强制翻译）、长段帮助说明、后端返回的错误原文。

### 3.6 类型安全（可选增强）
- 可用 `TypeScript` 声明让 `t()` 的 key 受类型约束（i18next `resources` 类型推导）。v1 可先做宽松版（key 为 `string`），后续收紧；不影响功能。

## §5 决策（2026-07-28 全部锁定）
- **D1 · 后端错误文案是否 v1 本地化**：**否**——v1 仅前端 UI 文案双语；后端返回的中文错误原文（如 discovery 提示）仍按原样展示（`CredentialForm` 的 `getErrorMessage(err)` 透传）。后续可加 `Accept-Language` 头 + 后端错误码映射实现后端双语（需另行设计，不在本范围）。
- **D2 · 资源格式**：**`.ts` 资源对象**（`src/locales/zh-CN.ts` / `en-US.ts`），`en-US.ts` 以 `Resources = typeof zhCN` 类型约束保证两套结构镜像、key 对称由 `src/__tests__/i18n-symmetry.test.ts` 强制。
- **D3 · 默认语言**：**`zh-CN`**（与现状一致，不破坏现有用户体验）；偏好持久化 `localStorage('app-locale')`，刷新恢复，回退 `zh-CN`。
- **D4 · v1 抽取边界**：**UI 框架级文案全做**（导航菜单 / 登录页 / 各页标题与主按钮 / 表单标签 / Empty·Alert·Popconfirm / `message.*` 提示 / 列头）；**领域数据不做**（agent/workflow 用户自定义描述、节点配置 prompt 模板示例值、后端事件原文匹配 `'检索失败'` 等逐字比对逻辑保留中文）。

## §6 风险
- 🟡 中风险：涉及几乎所有前端页面文案抽取，工作量大；key 命名需团队统一规范，否则易碎片化。缓解：先定 `common`/`nav`/`login` 等高频命名空间，按 §3.5 优先级分批改造，每批小步提交。
- 长文案（句子级）双语维护成本：建议抽取时保留中文为 `fallbackLng`，英文缺失时回退中文而非空白。
- 第三方组件内置文案：仅 Antd/dayjs 经 `ConfigProvider` 解决；其余（如 `@xyflow/react` 画布右键菜单）v1 可能仍为中文，列已知残留。
